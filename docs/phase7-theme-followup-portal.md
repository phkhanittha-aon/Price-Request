## 3. หน้ารวมผู้บริหาร — เว็บแยก (ไม่อยู่ในระบบ Food)
หน้ารวมเป็น **web app แยกต่างหาก** (โฟลเดอร์ `portal/` = โปรเจกต์ Apps Script ของตัวเอง มีลิงก์ /exec ของตัวเอง)
เป็นหน้าทางเข้าก่อนเลือกระบบ: ดูภาพรวมการทำราคาทั้ง Food และ Mech แล้วกดปุ่มเพื่อเข้าเว็บทำราคาของแต่ละฝั่ง
ระบบ Food ไม่มีหน้ารวมอยู่ข้างใน และหน้ารวมไม่แก้ข้อมูลของทั้ง 2 ระบบ (สิทธิ์อ่านอย่างเดียว `spreadsheets.readonly`)

- ปุ่มใหญ่ **Food →** (เปิด MGS Food Price Request) และ **Mech →** (เปิด MGS Project Pricing)
- ตัวเลขรวม: งานทำราคาที่เปิดอยู่ · รอผู้บริหารอนุมัติ · ราคาถึง Sales รอลูกค้า · ปิดการขายได้
- การ์ดแต่ละระบบ: ขั้นตอน (คำขอ → ทำราคา → รออนุมัติ → ถึง Sales → ปิดได้) · มูลค่ารอปิด / ปิดได้ · GP % · อัตราปิด · รายการรออนุมัติ · แนวโน้ม 6 เดือน
  - Food: อ่านแท็บ Tickets / TicketItems / Quotations / Settings (มูลค่า = ราคาขาย × ปริมาณ/เดือน)
  - Mech: อ่านแท็บ Quotations เฉพาะคอลัมน์สรุป (ไม่อ่าน Detail) · USD × Exrate ของใบ · สกุลอื่นแจ้งแยก
  - สถานะ Mech: SR Submitted = คำขอ · Accepted / Requested / In Progress = ทำราคา · Submitted / Partial Approved = รออนุมัติ · Approved = รอปล่อยราคา · Pending = ถึง Sales · Won · Closed
- อัปเดตทุก 5 นาที (ปุ่มรีเฟรชดึงใหม่ทันที)
- ผู้มีสิทธิ์: Food role gm / admin / sr_manager **หรือ** อีเมลใน `PORTAL_ALLOWED_EMAILS` (เช่น BD Mgr / Procurement Mgr ฝั่ง Mech) · Sales / Sales Manager / SR เปิดไม่ได้

### ติดตั้ง (ครั้งเดียว)
1. สร้างโปรเจกต์ Apps Script ใหม่ชื่อ “MGS Price Request Portal” → วาง `portal/Code.gs`, `portal/Portal.html`, `portal/appsscript.json`
2. Project Settings → Script properties:
   | Key | ค่า |
   |---|---|
   | `FOOD_SHEET_ID` | ID ไฟล์ฐานข้อมูล Food (= `DB_SPREADSHEET_ID` ของระบบ Food) |
   | `FOOD_WEBAPP_URL` | ลิงก์ /exec ของ MGS Food Price Request |
   | `MECH_SHEET_ID` | ID ไฟล์ Google Sheets ของ MGS Project Pricing |
   | `MECH_WEBAPP_URL` | ลิงก์ /exec ของ MGS Project Pricing |
   | `PORTAL_ALLOWED_EMAILS` | (ไม่บังคับ) อีเมลผู้บริหารเพิ่มเติม คั่นด้วย , |
3. แชร์ไฟล์ Sheets ทั้ง 2 ไฟล์ให้บัญชีที่ deploy หน้ารวมแบบ **Viewer**
4. Run `checkPortalSetup()` → แก้ตามที่แจ้ง
5. Deploy → New deployment → Web app · Execute as: **Me** · Who has access: **Anyone within บริษัท**
6. ใช้ลิงก์ /exec ของหน้ารวมเป็นหน้าเว็บทางเข้าของผู้บริหาร (bookmark / ใส่ใน Lark)

ทดสอบ: `node dev/portal-test.js` (21 เทสต์) · prototype: `node dev/build-portal-prototype.js prototype/mgs-portal.html`

## 4. ติดตามงานขาย — มุมมองฝั่ง Sourcing รายคน (v2026.10.10-1)
ใช้ใน weekly meeting: SR ติดตามกับ Sales ว่าราคาที่ตัวเองทำไปแล้ว ลูกค้าตอบอย่างไร
- SR มีเมนู **🎯 ติดตามงานขาย** → เปิดมาเป็น “ราคาที่ฉันทำ — ติดตามกับ Sales” (กรองตาม SR ผู้ทำราคาอัตโนมัติ)
- SR Manager / GM / Admin / Sales Manager: ปุ่ม **🏭 Sourcing** → การ์ดต่อ SR (ทำราคาแล้ว · รอลูกค้า · อัปเดตสัปดาห์นี้ · ปิดได้ · ไม่ได้ · อัตราปิด · มูลค่ารอปิด) → กดเพื่อดูงานของ SR คนนั้น
- ปุ่ม **📋 สรุปสำหรับประชุมประจำสัปดาห์**: คัดลอกข้อความแยกตาม Sales — สินค้า · ลูกค้า · ปริมาณ/เดือน · ราคาขาย · สถานะ · อัปเดตล่าสุด · ขั้นตอนถัดไป
- **ไม่มีต้นทุน / GP / ชื่อ Supplier** — ข้อมูลชุดเดียวกับที่ Sales เห็น · SR ดูได้อย่างเดียว (ผลการขายยังอัปเดตโดย Sales / Sales Manager)

## 5. SR Manager / GM แก้ราคาได้ในขั้นอนุมัติของตัวเอง (v2026.10.10-1)
- ขั้น **รอ SR Manager ตรวจราคา** → SR Manager แก้ได้ · ขั้น **รอ GM อนุมัติฝั่งซื้อ** → GM แก้ได้ (ปุ่ม **✏️ แก้ไขราคา** ในหน้ารายละเอียดใบ)
- แก้ได้: ราคา vendor, สกุลเงิน / FX, VAT, ค่าเคลียร์ของ, เงื่อนไข, เลือกผู้ชนะ (+ เหตุผลถ้าไม่ใช่เจ้าถูกสุด), GP % · ไม่ได้: แยกรายการ “ไม่เสนอ / ส่งตามหลัง” (SR เท่านั้น), แนบรูป
- ระหว่างนั้น SR แก้ไม่ได้ (กันแก้ทับกัน) · กด “บันทึกการแก้ไข” แล้วกลับไปกดอนุมัติ
- ตอนอนุมัติ: ระบบคำนวณราคาขายใหม่จากราคาที่แก้ · บันทึกจำนวนครั้งที่แก้ใน log · แจ้ง SR ผู้ทำราคา (“✏️ … แก้ไขราคา n ครั้งก่อนอนุมัติ”) · ทุกการแก้ไขอยู่ใน Timeline ภายใต้ชื่อผู้แก้ (Sales ไม่เห็น)

## 6. ติดตามการขาย › ⏳ งานค้าง (v2026.10.10-2)
ปุ่ม **⏳ งานค้าง** (ทุกบทบาทที่เปิดหน้าติดตามการขาย): แสดง **เฉพาะรายการที่ยังไม่ปิด** แยกตามเรื่องที่ค้าง เรียงจากที่ไม่ได้อัปเดตนานที่สุด
| กลุ่ม | เข้ากลุ่มเมื่อ |
|---|---|
| 🆕 ยังไม่เคยอัปเดต | ได้ราคาแล้วแต่ Sales ยังไม่เคยบันทึกผล |
| 🧪 ตัวอย่างสินค้า | ผลการขาย “ส่งตัวอย่าง” หรือสถานะ / ขั้นตอนถัดไปเกี่ยวกับตัวอย่าง |
| 💬 เรื่องราคา | ลูกค้าเทียบราคา / ต่อรองราคา หรือขั้นตอนถัดไป “ขอปรับราคาจาก SR” |
| ⏳ รอลูกค้าตัดสินใจ | เพิ่งส่งราคา · รออนุมัติภายในของลูกค้า · ลูกค้าเลื่อนโครงการ |
| 🤝 ใกล้ปิด / รอ PO | ใกล้ปิดการขาย หรือขั้นตอนถัดไป “รอ PO / ปิดการขาย” |
| 📌 กำลังติดตาม | ยังไม่ได้ระบุสถานะกับลูกค้า |
- ติ๊ก “เฉพาะที่ต้องอัปเดต” เพื่อดูเฉพาะที่ถึงวันนัด / เกิน 7 วัน · แตะชิปด้านบนเพื่อเลื่อนไปกลุ่มนั้น
- ใช้ร่วมกับตัวกรอง Sales / SR ได้ (เช่น SR เปิด “ราคาที่ฉันทำ” แล้วกด ⏳ งานค้าง ใน weekly meeting) · Sales กด 📝 อัปเดต ได้จากในกลุ่มเลย
- ข้อความสรุปประชุมประจำสัปดาห์บอกกลุ่มที่ค้างของแต่ละรายการ · ไม่มีต้นทุน / GP
