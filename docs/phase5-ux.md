# Phase 5 — ปรับปรุง UX: กรอกน้อยลง · ฐานข้อมูล Supplier · หน้าแรกตามบทบาท · รายการไม่ค้าง

อ้างอิง Requirement: เอกสาร “MGS Food Price Request — Requirement รอบปรับปรุง UX (Phase 5)” · พัฒนาตามลำดับในเอกสาร 1 → 5

## 1. รายการใบเสนอราคา + Filter (แก้อาการเด้ง / ค้าง)

| สาเหตุเดิม | แก้แล้ว |
|---|---|
| เปลี่ยนตัวกรองแต่ละครั้ง = อ่าน Google Sheet ใหม่ทั้งชีต (2–5 วินาที) | เปิดหน้า = เรียก `listTicketBoard` **ครั้งเดียว** แล้วกรอง / ค้นหา / นับ / เรียง ในเบราว์เซอร์ (ทันที) |
| ผลที่มาช้าเขียนทับผลใหม่ | ทุก request มีเลขลำดับ คำตอบเก่าถูกทิ้ง |
| ตารางหายกลายเป็นตัวโหลด หน้ากระโดด | ตารางเดิมยังอยู่ (จางลง) ระหว่างโหลดข้อมูลล่าสุด |
| “ล้างตัวกรอง” ไม่ล้างเงื่อนไขที่มากับลิงก์ | ตัวกรองอยู่ใน URL ที่เดียว ล้าง = เปลี่ยน URL ด้วย · Back / รีเฟรช ได้เงื่อนไขเดิม |
| 3 ตัวกรองซ้อนกัน (ผล / สถานะ / ขั้นตอน) | **แถบสถานะ** คลิกเดียว + ตัวเลขทุกแท็บ |

- ค่าเริ่มต้น = **ทั้งหมด** เรียง “งานค้างและเร่งด่วนก่อน” ใบปิดงานอยู่ท้าย
- แท็บ: ทั้งหมด · รอฉัน · ของฉัน (Sales/SR) · คิวรอรับงาน (SR) · รออนุมัติฝั่งขาย · SR กำลังหาราคา · รอตรวจราคา · ส่งถึง Sales · 📌 ส่งตามหลัง · ปิดงาน · ไม่อนุมัติ/ยกเลิก
- ช่องค้นหาเดียว (เลขที่ / ลูกค้า / สินค้า / Sales / SR) ผลเปลี่ยนขณะพิมพ์
- “⚙ ตัวกรองเพิ่มเติม” เปิดแผงด้านข้าง: ขั้นตอน, กลุ่มสินค้า, Sales, SR, ความเร่งด่วน, ช่วงวันที่, การเรียง — ทำงานเมื่อกด **ใช้ตัวกรอง**
- ตัวกรองที่ใช้อยู่แสดงเป็นป้าย ✕ ทีละอัน + “ล้างทั้งหมด” · ไม่พบผล → ปุ่ม “ล้างตัวกรองแล้วแสดงทั้งหมด”
- Server cache 5 นาทีต่อผู้ใช้ และล้างทันทีที่มีการเขียนข้อมูลใบ / รายการ / ผู้ใช้ / Settings (`DATA_VERSION`) — ไม่มีวันเห็นข้อมูลเก่ากว่าการแก้ล่าสุด
- แถวรายการไม่มีราคาหรือต้นทุน (ทดสอบแล้ว)

## 2. โมดูล Supplier (เมนู “Supplier”)

- เก็บในแท็บ **Vendors** เดิม (เพิ่มคอลัมน์) ใบเสนอราคาเก่าจึงผูก `vendor_id` เดิมได้ ไม่ต้องย้ายข้อมูล · รหัสใหม่ `SUP-0001`
- **ไม่มีขั้นอนุมัติ:** SR เพิ่มแล้วใช้ในใบได้ทันที
- ข้อมูล: ชื่อ, ชื่อเรียก/คำค้น, เลขผู้เสียภาษี, ประเภท (ในประเทศ/นำเข้า), ประเทศ, สกุลเงิน, VAT, เงื่อนไขชำระ, Incoterm, Lead time, MOQ, จำนวนวันยืนราคา, ค่าเคลียร์ประมาณการ (บาท/กก.), แบรนด์, กลุ่มสินค้าที่ขาย, ผู้ติดต่อ, ใบรับรอง + วันหมดอายุ, หมายเหตุคุณภาพ
- กันซ้ำ: ชื่อเดียวกันหลังตัดคำ “บริษัท / จำกัด / Co., Ltd. / PCL …” = **ไม่ให้บันทึก** · เลขผู้เสียภาษีซ้ำ = ไม่ให้บันทึก · ชื่อคล้าย = ถามยืนยันครั้งเดียว
- สิทธิ์: SR / SR Manager / Admin เพิ่ม-แก้ · GM ดูอย่างเดียว · **Sales / Sales Manager ไม่เห็นเลย** (เมนู, API และรายชื่อ Supplier ใน bootstrap — เดิมรายชื่อ vendor ถูกส่งให้ทุกคน แก้แล้ว)
- SR Manager / Admin: ปิด/เปิดใช้งาน (ปิดแล้วไม่ขึ้นในการค้นหา) · **รวมรายชื่อซ้ำ** (ย้ายใบเสนอราคาไปผูกรายการที่เก็บไว้ แล้วปิดรายการซ้ำ)
- ทุกการแก้ไขเก็บใน **SupplierLogs** (ใคร เมื่อไร ค่าเดิม → ค่าใหม่) ดูได้จากปุ่ม “ประวัติการแก้ไข” · แก้ทับกันใช้ version
- ใบรับรองหมดอายุ / ใกล้หมด (30 วัน) = ป้ายเตือน ไม่บล็อก · SR Manager / GM เห็นป้ายในหน้ารายละเอียดใบตอนตรวจราคา
- `setupDatabase` สร้าง Supplier จากชื่อ vendor ที่เคยพิมพ์ในใบเก่าให้อัตโนมัติและผูก `vendor_id` (รันซ้ำได้ ไม่สร้างซ้ำ)

## 3. ค้นหา Supplier ในหน้าเทียบราคา

1. กด “+ เพิ่ม Vendor” → 2. พิมพ์ค้นหา (ชื่อ / ชื่อย่อ / รหัส / เลขภาษี / แบรนด์) → 3. เลือก (↑ ↓ Enter ได้)
4. ระบบเติม สกุลเงิน, อัตราแลกเปลี่ยน, VAT, เงื่อนไขชำระ, Incoterm, MOQ, Lead time, ยืนราคาถึง, ค่าเคลียร์ (ถ้าหน่วยเป็น กก.), Origin + สเปก/Packing/อายุสินค้าจากใบล่าสุดของ Supplier นี้ — ช่องที่เติมให้ **พื้นเส้นประ** แก้ได้ทุกช่อง
5. **ราคาต่อหน่วย SR กรอกเอง** — ราคาครั้งก่อนแสดงเป็นคำแนะนำใต้ช่อง (ราคา · วันที่ · เลขใบ) ไม่เติมให้
6. ไม่เจอ → “+ เพิ่ม Supplier ใหม่” แบบย่อ (ชื่อ ประเภท สกุลเงิน VAT) ไม่ต้องออกจากหน้า แล้วใช้ในใบทันที
- ผลค้นหาเรียง: เคยเสนอสินค้านี้ → เคยเสนอกลุ่มเดียวกัน → ขายกลุ่มสินค้านี้ → ชื่อ · สูงสุด 8 รายการ
- เปลี่ยน Supplier หลังแก้ช่องเอง → ถามก่อนเขียนทับ
- “↺ ตั้งเป็นค่าเริ่มต้น” = บันทึกเงื่อนไขของใบนี้เป็นค่าเริ่มต้นของ Supplier (ใบเก่าไม่เปลี่ยน — ใบเสนอราคาเก็บสำเนาค่า ณ วันบันทึก)

## 4. ค่าเริ่มต้น (แก้ได้ทุกช่อง)

| ช่อง | ค่าเริ่มต้น | ตั้งค่าที่ |
|---|---|---|
| อัตราแลกเปลี่ยน | **USD = 35** (สกุลอื่นกรอกเอง) | Settings `fx_defaults` |
| ยืนราคาถึง | วันนี้ + วันยืนราคาของ Supplier (ไม่มี = 30 วัน) | Supplier / Settings `default_validity_days` |
| วันที่ต้องการราคา (Sales) | วันนี้ + 3 วันทำการ · ปุ่มลัด +3 / +5 / +2 สัปดาห์ | Settings `default_due_working_days` |
| ชื่อลูกค้า (Sales) | เลือกจากลูกค้าในใบของตัวเอง → เติมเอกสารที่ลูกค้านี้ขอครั้งล่าสุด | — |
| เอกสาร (Sales) | ปุ่มเลือก COA · Health Certificate · Halal · Spec sheet · … + พิมพ์เพิ่มได้ | Settings `document_options` |
| ชื่อสินค้า (Sales) | เลือกจากสินค้าที่ตัวเองเคยขอ → เติม ประเภท, NW, Size, Packing, หน่วย | — |
| หน่วย | กก. | — |
| ราคาเป้าหมาย | ติ๊ก “ไม่มีราคาเป้าหมาย” แทนการพิมพ์ 0 | — |
| ทั้งใบ | ปุ่ม “📄 สร้างใบใหม่จากใบนี้” (คัดลอกลูกค้า เอกสาร สินค้า — ไม่คัดลอกรูปและวันที่) | — |
| GP % | 15 (เดิม) | Settings `default_gp_percent` |

ข้อมูลประวัติของ Sales มาจาก **ใบของตัวเองเท่านั้น** (ทดสอบแล้วว่าไม่เห็นลูกค้าของ Sales คนอื่น)

## 5. หน้าแรกตามบทบาท + เมนู ≤ 5 รายการ

- **หน้าแรก:** 3 ตัวเลข (รอฉัน · กำลังดำเนินการ · เกินกำหนด) → แตะแล้วไปรายการที่กรองไว้ · ปุ่มลัดตามบทบาท · **งานที่ต้องทำ** เรียงตามความเร่งด่วน (10 แถว) · รายการส่งตามหลังที่ค้าง · Admin: สถานะ Lark 24 ชม.
- ปุ่มลัด: Sales = สร้างใบขอราคา · SR = คิวรอรับงาน, Supplier · SR Manager = รอตรวจราคา, งานยังไม่มี SR รับ · GM = อนุมัติฝั่งขาย, อนุมัติฝั่งซื้อ (มีตัวเลข) · Sales Manager = รออนุมัติ
- **รายงาน** (สถิติเดิม: ช่องสรุป แยกตาม Sales / SR) — Sales Manager, SR Manager, GM, Admin
- เมนู: Sales 3 · SR 3 · SR Manager 4 · Sales Manager 3 · GM 5 · Admin 4 รายการ (สถานะต่างๆ ย้ายไปเป็นแท็บในหน้าใบเสนอราคา)
- **UsageLog:** บันทึกจำนวนครั้งที่เปิดแต่ละหน้า (ส่งรวมไปกับ poll ทุก 60 วินาที ไม่เพิ่ม request) → ใช้ทบทวนหลัง 2 สัปดาห์ว่าหน้าไหนไม่มีคนใช้

## หลังวางโค้ด
1. วางไฟล์ `gas/` ทั้งหมด (ไฟล์ใหม่: `Suppliers.gs`, `PageSuppliers.html`, `PageHome.html`)
2. Run `setupDatabase` → เพิ่มคอลัมน์ Vendors, แท็บ SupplierLogs + UsageLog, Settings ใหม่ (`fx_defaults`, `default_validity_days`, `default_due_working_days`, `document_options`) และสร้าง Supplier จากใบเก่า
3. Run `runAcceptanceTests` → ทั้งหมดต้องผ่าน · Deploy **New version**
