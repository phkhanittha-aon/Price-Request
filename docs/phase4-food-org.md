## 2. โครงสร้างองค์กรและสายอนุมัติ
```
ขอราคา :  Sales ──► Sales Manager ──► GM ──► (SR หาราคา)
                    └─ ข้ามได้: ถ้าแผนกยังไม่มี Sales Manager ใบจะวิ่งตรงถึง GM
อนุมัติราคา: SR ──► SR Manager ──► GM ──► ส่งถึง Sales      (ห้ามข้ามขั้น)
```

| Role | ทำอะไร | เห็นอะไร |
|---|---|---|
| Sales | สร้าง/แก้ใบ (ก่อนอนุมัติ), รับทราบราคา / ขอปรับราคา | ใบของตัวเอง |
| Sales Manager (`manager`) | อนุมัติ/ไม่อนุมัติ/ส่งกลับ ใบของแผนกที่ตัวเองเป็น `manager_email` | **ทุกใบ** |
| GM | อนุมัติคำขอ + **อนุมัติราคา** (หรือส่งกลับให้ SR แก้) | ทุกใบ |
| SR | รับงาน, ตรวจเอกสาร, หาราคา, ส่งราคาให้ SR Manager | ใบที่ GM อนุมัติแล้ว (Dashboard = งานของตัวเอง) |
| SR Manager (`sr_manager`) — **role ใหม่ แทน SR Lead** | มอบหมายงาน SR, **ตรวจ/อนุมัติราคา** หรือส่งกลับให้ SR แก้ | ใบที่ GM อนุมัติแล้ว (ทุกคน) |
| Admin | จัดการ master data, ตรวจ log | ทุกใบ |

**ข้าม Sales Manager**: ระบบดูที่แท็บ Departments → `SALES-FOOD.manager_email` — ถ้าว่าง หรือผู้ใช้นั้นไม่ใช่ role `manager` / ถูกปิดใช้งาน ใบจะไปขั้น "รอ GM อนุมัติ" ทันที (บันทึก `sales_manager_skipped: true` ใน log) · เมื่อมี Sales Manager แล้ว ใส่อีเมลในช่องนี้ ระบบจะใช้ขั้นนี้ทันที
**ห้ามข้ามขั้นราคา**: GM อนุมัติราคาได้เฉพาะเมื่อ SR Manager อนุมัติแล้ว · ถ้า SR Manager หรือ GM ส่งกลับ SR ต้องส่งใหม่เข้า SR Manager ทุกครั้ง · ผู้หาราคาอนุมัติราคาของตัวเองไม่ได้

| ขั้นตอน (stage) ใหม่ | Main status | ผู้รับผิดชอบ | SLA เริ่มต้น |
|---|---|---|---|
| `pending_sr_manager` รอ SR Manager ตรวจราคา | On Process | SR Manager | 8 ชม. |
| `pending_gm_price` รอ GM อนุมัติราคา | On Process | GM | 8 ชม. |

## 7. ราคาขาย (SR): ต้นทุน + ค่าเคลียร์ของ + GP — แสดงต่อหน่วยเท่านั้น

SR กรอก **ค่าเคลียร์ของ (บาท/หน่วย)** ในแต่ละ vendor และ **GP %** ต่อรายการสินค้า ระบบคำนวณให้ทันทีทั้งในหน้าใบเสนอราคาและฝั่ง server (server เป็นตัวตัดสินสุดท้าย)

| บรรทัด | สูตร (บาท ต่อหน่วย) |
|---|---|
| ต้นทุนสินค้า | ราคา vendor ถอด VAT (ถ้ารวม VAT) × อัตราแลกเปลี่ยน |
| + ค่าเคลียร์ของ | ที่ SR กรอก (ว่าง = 0) เช่น ค่าชิปปิ้ง ภาษีนำเข้า ค่าขนส่งถึงคลัง |
| **= ต้นทุนถึงคลัง** | ต้นทุนสินค้า + ค่าเคลียร์ของ — **ใช้ตัดสิน “ถูกที่สุด”** (เทียบ CIF กับส่งถึงคลังได้แฟร์) |
| + กำไร GP | ราคาขาย − ต้นทุนถึงคลัง |
| **= ราคาขาย** | ต้นทุนถึงคลัง ÷ (1 − GP%) · ปัด 2 ตำแหน่ง |
| ราคาเป้าหมายลูกค้า | เทียบกับราคาขาย (▲ สูงกว่าเป้า x% / ✓ ต่ำกว่าเป้า) |

- GP คิดเป็น **% ของราคาขาย** (margin) ไม่ใช่ markup · ว่างไว้ = ใช้ค่าเริ่มต้นจาก Settings `default_gp_percent` (15) · รับค่า 0–99.99
- หน้าใบเสนอราคา: ตาราง “ราคาขาย (ต่อหน่วย)” ใต้แต่ละสินค้า + การ์ด **สรุปราคาขาย (ต่อหน่วย)** ทุกรายการ (ผู้ขาย · ต้นทุนสินค้า · ค่าเคลียร์ · ต้นทุนถึงคลัง · GP · กำไร · ราคาขาย · เป้าหมาย)
- **ตัดยอดรวมออก** (รวมสุทธิ / รวมจ่ายจริง) ทั้งหน้าใบเสนอราคา หน้ารายละเอียดใบ และหน้ายืนยันส่งราคา — แสดงเฉพาะต่อหน่วย
- เมื่อส่งราคา ระบบบันทึก `gp_percent` และ `sell_price_thb` ลงรายการสินค้า และเขียน log · เปลี่ยน GP ระหว่างร่างจะ log เป็น “กำหนด GP %”
- SR Manager / GM เห็นตารางเดียวกันในหน้ารายละเอียดใบตอนตรวจราคา · Sales เห็นหลัง GM อนุมัติราคา

**หลังวางโค้ด:** Run `setupDatabase` → เพิ่มคอลัมน์ `Quotations.clearance_thb`, `Quotations.landed_unit_cost_thb`, `TicketItems.gp_percent`, `TicketItems.sell_price_thb` และ Settings `default_gp_percent` ให้อัตโนมัติ · ใบเสนอราคาเดิมที่ไม่มีค่าเคลียร์ = 0 · `runAcceptanceTests` → **201/201**

|---|---|
| Server acceptance | **201/201** — ใหม่: สูตรต้นทุนถึงคลัง/ราคาขาย, “ถูกที่สุด” ตามต้นทุนถึงคลัง, GP ว่าง = ค่าเริ่มต้น, GP ไม่ถูกต้องถูกปฏิเสธก่อนเขียน, ราคาขายบันทึกตอนส่ง, Sales เห็นราคาขายหลัง GM อนุมัติ |

## 8. Sales เห็นเฉพาะราคาขาย · แจ้งกลุ่ม Lark เมื่อทำราคาเสร็จ · หน้าจอแบบ ERP

### 8.1 สิทธิ์การเห็นราคา (บังคับที่ server — browser ไม่ได้รับข้อมูลต้นทุนเลย)
| ผู้ใช้ | เห็น |
|---|---|
| SR · SR Manager · GM · Admin | ราคา vendor ทุกเจ้า, ค่าเคลียร์ของ, ต้นทุนถึงคลัง, GP, กำไร, ไฟล์ใบเสนอราคา vendor |
| **Sales · Sales Manager** | **ราคาขายต่อหน่วยเท่านั้น** หลัง GM อนุมัติราคา + ราคาเป้าหมาย/ส่วนต่าง, ยืนราคาถึง, แบรนด์, Origin, Packing, อายุสินค้า, MOQ, Lead time |

ฝั่ง Sales **ไม่ได้รับ**: ชื่อ vendor, ราคา vendor/สกุลเงิน/VAT, Incoterm, ค่าเคลียร์, ต้นทุน, GP, กำไร, เหตุผลเลือก vendor, ไฟล์ใบเสนอราคา vendor
- ประวัติ (timeline) ของ Sales: ซ่อนรายการเพิ่ม/แก้ราคา vendor และกำหนด GP · ขั้นตอนตรวจราคา (ส่งราคา / SR Manager / GM) แสดงเป็นสถานะอย่างเดียว ไม่แสดงความเห็นของผู้ตรวจ
- แจ้งเตือนถึง Sales ในขั้นตรวจราคา: ไม่แนบความเห็นของ SR Manager / GM (อาจพูดถึงต้นทุน/GP) — ผู้ตรวจด้วยกันยังเห็นความเห็นครบ

### 8.2 แจ้งกลุ่ม Lark เมื่อทำราคาเสร็จ
เมื่อ GM อนุมัติราคา ระบบส่งการ์ดสีเขียว **“✅ [PR-xxxx] ทำราคาเสร็จแล้ว”** เข้ากลุ่ม: ลูกค้า, Sales, SR, รายการสินค้า (Size · Packing) + **ราคาขายต่อหน่วย** + ยืนราคาถึง + ปุ่มเปิดใบ — **ไม่มีต้นทุน/GP** เพราะในกลุ่มมี Sales
- ตั้งค่า: Script Properties → `LARK_PRICE_GROUP_CHAT_ID` = chat_id ของกลุ่ม (oc_xxx) และเพิ่ม Bot เข้ากลุ่ม · ว่างไว้ = ใช้ `LARK_GROUP_CHAT_ID` เดิม
- ส่งผ่านคิวแจ้งเตือนเดิม (retry 5 ครั้ง) · ถ้า Lark ล่ม ไม่กระทบการอนุมัติ · ดูสถานะได้ในแท็บ Notifications (`user_email = #price_group`)

### 8.3 หน้าจอแบบ ERP
- แถบบน: โลโก้ MGS ERP · breadcrumb “โมดูล › หน้า” · ผู้ใช้ · การแจ้งเตือน
- **เมนูโมดูลอยู่ขวามือ** แบ่งกลุ่ม: ภาพรวม · งานของฉัน · ใบขอราคา · จัดหาราคา (Sourcing) — แสดงเฉพาะเมนูตามสิทธิ์, ตัวเลขงานรอฉัน
- ปุ่ม ⇥ ย่อเมนูเหลือไอคอน (จำค่าไว้ในเบราว์เซอร์) · มือถือ/แท็บเล็ต (≤ 900px): ปุ่ม ☰ มุมขวาบน เปิดเมนูเลื่อนจากขวา

**ผลทดสอบ:** Server acceptance **208/208** (ใหม่: Sales/Sales Manager ไม่ได้รับข้อมูลต้นทุนทั้งใน items, timeline, ไฟล์ · แจ้งเตือน Sales ไม่มีความเห็นผู้ตรวจ · กลุ่ม Lark ได้ข้อความเดียว มีแต่ราคาขาย และส่งถึง chat ที่ตั้งไว้) · Browser: เมนูขวา desktop/ย่อ/มือถือ, หน้าใบของ Sales แสดงราคาขายอย่างเดียว, flow ครบไม่มี JavaScript error

### 9.1 Sales เห็นเฉพาะ “ราคาขายของใบตัวเอง จากผู้ชนะเจ้าเดียว”
ตรวจทุกช่องทางที่ข้อมูลออกจาก server แล้ว:

| ช่องทาง | ก่อน | หลังแก้ |
|---|---|---|

### 9.2 GM อนุมัติ 2 ฝั่ง แยกชัดเจน
| | ฝั่งขาย 🛒 | ฝั่งซื้อ 📦 |
|---|---|---|
| ขั้นตอน | `pending_gm` “รอ GM อนุมัติฝั่งขาย” | `pending_gm_price` “รอ GM อนุมัติฝั่งซื้อ” |
| GM ตรวจ | คำขอของ Sales: ลูกค้า สินค้า ปริมาณ ราคาเป้าหมาย | ราคาซื้อ vendor, ต้นทุนถึงคลัง, GP, ราคาขาย (หลัง SR Manager) |
| ผลเมื่ออนุมัติ | ส่งให้ SR หาราคา | ส่งราคาขายถึง Sales + แจ้งกลุ่ม |

เมนู GM มี **“อนุมัติฝั่งขาย”** และ **“อนุมัติฝั่งซื้อ”** แยกกัน พร้อมตัวเลขงานรอ · หน้าใบมีแถบสี (น้ำเงิน = ขาย, เขียว = ซื้อ) บอกว่ากำลังอนุมัติฝั่งไหน

### 9.3 รายการที่ไม่เสนอ / ส่งตามหลัง (SR)
ในหน้าใบเสนอราคา แต่ละรายการมีปุ่ม:
- **✕ ไม่เสนอรายการนี้** — ใส่เหตุผล (บังคับ) · Sales เห็น “ไม่เสนอราคา + เหตุผล” · กด “↩ กลับมาเสนอราคา” ได้ระหว่างหาราคา
- **📌 ส่งตามหลัง (แยกเป็นงานค้าง)** — ใส่เหตุผล/กำหนด (บังคับ) → ระบบ **แยกรายการเป็นใบใหม่ทันที** (เลขใหม่ PR-YYYY-NNNN, ลูกค้า/Sales/SR เดิม, อนุมัติฝั่งขายเดิมติดไปด้วย, เอกสารที่ตรวจแล้วติดไป, ราคา vendor และรูปที่กรอกไว้ย้ายไป) · ใบเดิมส่งราคาต่อได้โดยไม่ต้องรอ · แก้กลับไม่ได้ · ส่งตามหลังทุกรายการในใบไม่ได้
- งานค้างแสดงที่: เมนู **📌 ส่งตามหลัง (ค้าง)** (มีตัวเลข) · การ์ดใน Dashboard · ป้าย “ส่งตามหลังจาก PR-xxxx” ในรายการ · ลิงก์ไป-กลับระหว่างใบเดิมกับใบใหม่
- แจ้งเตือน Sales ผู้ขอ + SR Manager เมื่อแยกงาน · DM ราคาขาย/ข้อความกลุ่มบอกรายการที่ไม่เสนอ/ส่งตามหลัง
